# 【11 月版本】未來方向：把 3D 資料轉成基因組

**日期：** 2026-11-16
**來源：** 你在 2026-11-16 提出的想法；下面是整理與可行性判斷。
**地位：** 不是這篇論文的主張。論文裡只在「後續工作」寫兩三句（見 `RTIS_新論文大綱.md` 第五之二節）。

---

## 一、你的想法

只要能錄入更多 3D 資料（動物本體、器官、骨骼，甚至 DNA），就可以讓系統的精度更高。

## 二、要先修正的一個詞：現在的系統沒有「訓練」

11 月的系統完全靠手寫的規則與六份手寫的基因組運作，裡面沒有機器學習。所以更多 3D 模型**不能直接餵進去**，系統也不會因為資料變多就自己變準。

缺的是一個**轉換器**：

```
3D 模型（網格） → 抽出骨架 → 切成部位 → 標上三層標籤 → 骨架基因組（BonePart 串）
```

有了轉換器，任何 3D 動物模型都能變成 RTIS 的親代，再用現有的遺傳規則交配。

## 三、各種資料可不可行

| 資料 | 可不可行 | 能帶來什麼 | 要先解決什麼 |
|---|---|---|---|
| 動物 3D 模型 | 可行，但轉換器本身就是一個研究題目 | 遠多於六種的形體，部位更真實 | 抽骨架、分部位、自動標標籤 |
| 骨骼 | 最直接：基因組本來就是骨架 | 更真實的比例與關節位置 | 骨骼資料的格式與部位命名要統一 |
| 器官 | 要先有內部結構才行 | 內部構造的遺傳 | 現在的系統只有外殼，基因組要先擴充 |
| DNA | 目前不可行 | 沒有可用的東西 | 生物學本身還不能從 DNA 推出身體形狀 |

**要寫清楚的一點：** RTIS 的「基因組」是工程上的設計，不是生物的 DNA。論文裡要寫明，避免審稿人誤解。

## 四、定位：這個方向和現有研究的分界

用大量 3D 資料訓練、直接生成生物的方法已經存在（例如 Muses，arXiv 2601.03256，2026 年 1 月：以骨架驅動、用 LLM 與 Trellis 生成混種生物）。它們沒有基因組，也沒有可追溯的遺傳。

所以這個方向比較強的版本是：

- **學習的工具負責「把 3D 模型變成基因組」**（轉換器）。
- **遺傳仍然用規則**，保持每個基因查得到來自哪一方。

這樣資料變多時，形體的數量與真實度提高，而 RTIS 自己的價值（可追溯的跨形體遺傳）不變。

## 五、可能的順序（之後的專案，不是現在）

1. 骨骼資料 → 基因組（最接近現有格式）。
2. 動物網格 → 抽骨架 → 基因組（需要現成的骨架抽取與部位分割方法，要先查文獻）。
3. 自動標標籤（可以用 LLM 或分類器，輸出三層標籤）。
4. 器官與內部結構（基因組要先擴充）。

每一步做之前都要先查文獻有沒有現成的方法；這裡列的是方向，還沒有查證。
